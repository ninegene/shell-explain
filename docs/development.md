# Development and verification

Stages 1–3 now have a local implementation. The project remains private; stage 4 next expands the command collection per [the checklist](command-collection.md). Current CLI/web usability is accepted; broader usability studies are deferred. No public binaries, installer, Homebrew tap, mise release, GitHub Pages deployment, or DNS configuration has been published.

## Prerequisites

- [just](https://github.com/casey/just), the development command runner (on macOS: `brew install just`).

- Go 1.24 or newer (module dependencies pinned in go.mod/go.sum).
- Node.js 22.23.4 or newer and npm; the tested environment uses Node 26.
- A local Bash for the authored-example checks. GNU/macOS/BusyBox examples run only when that individual command is identified as the requested implementation; unavailable or ambiguous tools are skipped explicitly. External-tool examples use /bin/sh; the cd examples require Bash.

Install web dependencies from the lockfile:

```sh
npm ci --prefix web
```

Go resolves the two pinned pure-Go dependencies when its commands first run. Normal use of the compiled CLI is offline. Dependency downloads are build-time activities, not runtime requests.

## Build and use the CLI

Run `just` or `just help` for the command guide. The default recipe prints usage and prerequisites without running builds or downloading dependencies. Explicit recipes describe their work, preserve tool diagnostics, and report output locations or successful completion. A failed step stops its recipe before any success message is printed.

```sh
just build
./bin/explain grep
./bin/explain grep --details
./bin/explain /usr/bin/grep
./bin/explain grep --implementation gnu --option=-n
./bin/explain sed --implementation apple --format json
./bin/explain cd --implementation bash
./bin/explain search search logs
./bin/explain list
```

Text output shows compact examples by default: `# ` descriptions, flush-left commands, and a blank line between examples. Both text modes use this format for example sections, preserving indentation authored inside multiline commands. The website preserves the separate code blocks authored in Markdown, each with its own copy button; option explanations remain grouped in a separate `Options` block. CLI examples contain no Markdown fences and use one blank line between examples. Compact descriptions have a 100-column cap; CLI option descriptions honor a smaller `--width`, while `--width=0` keeps the 100-column cap. Authored commands and indivisible inline literals are not split. Use `--details` for all selected sections, detection evidence and references, or `--option` to look up an option directly. JSON always includes all selected sections, independent of `--details`; list/search do not accept this command-lookup flag. Output is plain text when redirected. `--color=always|never|auto`, NO_COLOR, `--width`, and COLUMNS control presentation. Width affects prose only; fenced code and inline code spans are never split or whitespace-collapsed. A long inline command can exceed the requested width. No pager is launched. `--no-probe` disables native version probes.

The source Markdown is embedded directly by the content package. Go's build invalidation picks up changes automatically. `--version` includes the deterministic SHA-256 content revision; release version defaults to dev and can later be supplied through a linker flag.

## Validate/export shared content

```sh
just content
go run ./cmd/content-export --source content > /tmp/shell-explain-catalog.json
```

The exporter validates working-tree Markdown or the embedded collection and generates the same model used by the CLI. Astro loads this generated JSON through a content collection. The generated file is ignored by Git, and is regenerated by web dev/build/check commands. It is not an authoring source.

## Run the site locally

```sh
just web-dev
```

Open the localhost URL printed by Astro. Both `just web-dev` and `npm --prefix web run dev` watch Markdown in content/ for edits, additions, renames, and deletions. Changes are debounced and exported serially through the Go parser; Astro reloads the generated catalog automatically. Invalid content logs a validation error and leaves the last valid catalog available. Correct the Markdown and save again to recover without restarting. Catalog replacement is atomic so Astro cannot read a partially written JSON file.

To inspect production static output:

```sh
just web-build
npm --prefix web run preview -- --ignore-lock
```

The --ignore-lock flag keeps an agent-driven preview in the foreground so it can be stopped with Ctrl-C. Astro 7 may otherwise background preview/dev servers when it detects an agent. `npm test` (`just web-test`) runs the browser suite through `web/scripts/test-e2e.mjs`, which picks a free port, passes it to Playwright as `WEB_TEST_PORT`, serves a foreground preview there and cleans it up afterwards. It does not use Astro's dev port 4321, so `just web-dev` can keep running. Running `npx playwright test` directly falls back to port 4322.

## Verification commands

```sh
just test
just check
python3 -B scripts/test_linux_smoke.py
cd web
npx playwright install chromium
cd ..
just web-test
```

Go tests cover schema errors, unsupported/unsafe Markdown, deterministic revision, aliases/search, structured option selection, code preservation, CLI JSON parity/errors, text wrapping, and detection boundaries. Integration checks exercise macOS system tools and prefixed/unprefixed Homebrew GNU tools when available. A script wrapper test confirms it is not executed during identification. Native descendant fixtures verify process-group cleanup after timeout and parent exit, plus bounded output waiting when a child escapes into a new session.

Authored code examples run only inside isolated temporary fixture directories as an explicit test operation. This is not a CLI execution feature. The tests verify concrete output for log matching/range printing and verify that sed in-place examples preserve backup content.

The web test command first runs a development-server regression in a temporary repository copy, verifying live Markdown edits, added/deleted entries, and recovery after invalid content. Run it alone with `npm --prefix web run test:dev`. It does not alter the authored collection. Browser tests then build a fresh CLI and production site, compare every command/implementation page with the CLI's selected model and exact code text, exercise search/filter/tag navigation and clipboard copying, check canonical URLs, test no-JavaScript content, run desktop/mobile axe checks, verify no horizontal page overflow, and check keyboard access. They save desktop/mobile screenshots under the system temporary directory for visual review. Automated accessibility checks do not replace broader user testing, now tracked in the roadmap’s future usability backlog. The source formatter is pinned; use npm --prefix web run format to apply it and just check to verify formatting and types.

## Known limits

- The current corpus has twenty-three original entries; stage 4 continues to expand it: grep, sed, find, cd, cat, head, tail, wc, sort, uniq, cut, tr, ls, mkdir, cp, mv, rm, chmod, xargs, gzip, tar, stat, and date. Unknown commands/options return an explicit error rather than generated help.
- macOS system and Homebrew GNU examples are exercised when available. An optional real Linux smoke check also validates BusyBox/GNU selection and examples. These checks cover concrete tool builds, not every BusyBox configuration or historical version.
- FreeBSD/OpenBSD variants are not shipped. FreeBSD manual links are comparative references, not Apple version guarantees.
- Version banners are evidence for implementation selection, not proof of every documented option's availability. Every page states this limitation.
- The static site cannot inspect a visitor's installed commands. Its shareable implementation URLs make that choice explicit.
- The binary cannot inspect aliases/functions in the parent shell. Unknown wrappers remain ambiguous; optional shell integration is deferred.
- Code/content licenses and public contribution terms remain a stage-5 decision. All authored reference entries here are original; no third-party explanation corpus was imported.

## Optional real Linux smoke check

```sh
python3 scripts/linux-smoke.py
```

Requires Python 3, curl, Go, libarchive tar, and a separately installed qemu-system-x86_64. The script verifies the libarchive version banner and accepts bsdtar or macOS /usr/bin/tar, even when GNU tar comes first on PATH. Install bsdtar with the libarchive-tools package on Debian/Ubuntu. GNU tar does not read ISO 9660 images. This is not required for normal CLI use or the website. The script downloads the pinned Alpine 3.24.3 rootfs/virtual ISO from the official mirror and verifies their SHA-256 values, obtains GNU packages and dependency metadata over verified HTTPS, cross-compiles two static Linux test binaries, and boots a temporary RAM-only guest with networking disabled. It creates no host mounts, persistent VM disk, or cloud resources. Downloads are cached under ignored .cache/linux-smoke. APK package selection follows the branch's current index and prints exact versions; its checks are not a substitute for a signed release pipeline.

The guest tests actual BusyBox and GNU executable selection and runs every authored code example for the entries that declare BusyBox or GNU inside temporary fixtures, including expected log output and sed backup preservation. It prints LINUX_SMOKE_PASS only after those checks succeed. The test helper cmd/compat-check is not a distributed command.

Run `python3 -B scripts/test_linux_smoke.py` for extractor-selection unit tests without downloads or QEMU. These cover explicit bsdtar, macOS system tar with GNU tar first on PATH, libarchive tar on PATH, and rejection of GNU tar.
